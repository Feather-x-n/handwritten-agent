## 一、环境说明
项目分为开发、预发和生产三套环境，代码分别部署在 dev、staging、prod 三个命名空间。运行时使用 Python 3.12、Docker 24、MySQL 8.0 和 Redis 7，反向代理为 Nginx。生产环境位于华东区机房，预发环境与生产保持相同配置，仅数据量较小，用于发布前验证。

## 二、配置与环境变量
所有敏感配置通过环境变量注入，本地开发使用项目根目录的 .env 文件，该文件禁止提交到代码仓库。生产环境的密钥存放在密钥管理服务中，容器启动时以只读方式挂载，DEEPSEEK_API_KEY、数据库密码等不得写进镜像。修改配置后必须重启应用进程才能生效，热更新仅支持日志级别。

## 三、部署步骤
发布流程为：在发布分支执行 git pull 拉取最新代码，运行 pip install -r requirements.txt 安装依赖，执行 alembic upgrade head 完成数据库迁移，然后重启服务并访问 /healthz 健康检查接口。健康检查返回 200 且数据库连通才算发布成功，任一容器失败需立即停止发布并回滚。

## 四、发布窗口
常规发布窗口为工作日 10:00 至 16:00，周五下午和法定节假日前一天不发版，避免问题跨周末。紧急修复可走加急审批，需技术负责人和值班经理双签。每次发布需在变更管理系统登记版本号、变更内容和回滚方案，未登记的发布视为违规操作。

## 五、回滚方案
镜像仓库保留最近 5 个版本的 tag，回滚时执行 docker compose up -d app:vX 切换到上一个稳定版本，通常在 2 分钟内完成。数据库迁移默认不可自动回滚，涉及表结构变更的发布必须先做全量备份，并准备反向 SQL 脚本。回滚后需在群里同步原因和影响范围。

## 六、日志规范
应用日志写入 /var/log/app 目录，按天切割并保留 14 天；Agent 的 JSONL 调用记录保留 30 天，便于复盘。日志统一输出 JSON 格式，包含 time、level、trace_id 和 message 字段，排查问题时先按 trace_id 串联一次请求的完整链路。禁止在日志中打印密钥、密码和用户手机号。

## 七、监控与告警
监控使用 Prometheus 采集指标、Grafana 展示看板。核心告警规则：5xx 比例超过 1% 且持续 5 分钟、接口 P99 延迟超过 2 秒、容器 CPU 使用率超过 85% 持续 10 分钟。告警通过企业微信机器人推送到值班群，值班人员需在 10 分钟内响应并认领，超时自动升级到技术负责人。

## 八、数据库备份
MySQL 每天凌晨 2:00 执行全量 mysqldump 备份，同时保留 binlog 用于按时间点恢复，备份文件保留 7 天并异地存储一份。每季度进行一次恢复演练，在预发环境还原最近一次备份并校验关键表行数。恢复演练失败视为重大风险，需在两周内整改。

## 九、常见故障处理
端口被占用时用 lsof -i:8000 查看进程并确认是否可以终止；磁盘空间不足用 df -h 定位分区，清理 /var/log 下的历史日志；容器频繁 OOM 时用 dmesg 查看内核日志，并检查内存限制配置。数据库连接池耗尽的典型表现是请求超时陡增，可先重启 worker 缓解，再排查慢查询和连接泄漏。

## 十、安全基线
应用禁止以 root 用户运行，Dockerfile 中需指定非特权用户。生产环境必须关闭 debug 模式，避免异常堆栈泄露给外部。SSH 只能通过跳板机登录，密钥每 90 天轮换一次。依赖包每月扫描一次已知漏洞，高危漏洞需在 7 天内修复或给出缓解方案。
